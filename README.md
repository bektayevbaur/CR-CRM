# CR-CRM — Clean Republic CRM

CRM для химчистки обуви **Clean Republic** (Алматы). Статическое веб-приложение (HTML + JS) с базой данных **Firebase**: работает на GitHub Pages или любом другом статическом хостинге, с телефона и компьютера.

## Возможности

- **Заказы** — список с фильтром по статусу (Принят → В работе → Готов → Выдан / Отменён) и поиском по номеру, имени, телефону, бренду и боксу.
- **Приём** — оформление заказа: клиент (поиск по телефону, бонусы), обувь (бренд, подлинность, тип, размер, материал, цвет), до 6 фото, загрязнённость, тариф и доп. услуги, скидка/промокод, свободный бокс, забор и доставка.
- **Карточка заказа** — смена статуса, оплаты (наличные / карта / Kaspi Pay), фото «после», сообщение клиенту в WhatsApp.
- **Наряд-заказ** — печатная форма с условиями, выгрузка в PDF.
- **Клиенты** — база клиентов, история заказов, бонусы.
- **Касса** — выручка, средний чек, долги, разбивка по оплатам, точкам, каналам, тарифам и мастерам.
- **Настройки** — прайс, точки, мастера, менеджеры, боксы, ставки, реквизиты наряд-заказа, **сотрудники с доступом**.

**Демо без базы:** откройте сайт с `?demo` в конце адреса — всё работает, но данные живут только до перезагрузки.

## Файлы

| Файл | Что это |
|------|---------|
| `index.html` | приложение: интерфейс и логика |
| `js/backend.js` | работа с Firebase (вход, база, фото) и демо-режим |
| `firebase-config.js` | настройки вашего проекта Firebase — **заполнить** |
| `firestore.rules` | правила доступа к базе — вставить в Firebase Console |

## Как устроены данные (Firestore)

| Коллекция | Содержимое |
|-----------|------------|
| `orders` | заказы |
| `clients` | клиенты, id документа — телефон цифрами (`77071234567`) |
| `photos` | фото обуви (сжатый JPEG, до ~1 МБ на фото) |
| `config/main` | настройки из вкладки «Настройки» |
| `meta/counter` | счётчик номеров заказов |
| `staff` | сотрудники: id документа — email, поля `name`, `role` (`admin` / `staff`) |

Вход — через Google-аккаунт. Пускает только тех, кто есть в `staff`. Настройки и список сотрудников меняет только `admin`.

## Подключение Firebase (один раз, ~15 минут)

1. **Проект.** Зайдите на <https://console.firebase.google.com> → «Создать проект» → назовите, например, `clean-republic-crm`. Google Analytics можно выключить. Тариф — бесплатный **Spark**, карта не нужна.
2. **Вход.** *Build → Authentication → Get started → Sign-in method → Google → Enable* → укажите email поддержки → Save.
3. **База.** *Build → Firestore Database → Create database* → регион `eur3 (europe-west)` → «Start in production mode».
4. **Правила.** В Firestore откройте вкладку *Rules*, замените всё содержимым файла `firestore.rules` → *Publish*.
5. **Первый администратор.** В Firestore → *Data* → *Start collection*: ID коллекции `staff`, ID документа — **ваш Gmail маленькими буквами**, поля: `role` = `admin` (string), `name` = ваше имя (string) → Save. Остальных сотрудников потом добавляете прямо в CRM: *Настройки → Сотрудники*.
6. **Веб-приложение.** ⚙ *Project settings → General → Your apps → значок `</>`* → назовите → *Register app*. Скопируйте объект `firebaseConfig` и вставьте значения в `firebase-config.js`.
7. **Домен.** *Authentication → Settings → Authorized domains → Add domain* → домен сайта, например `bektayevbaur.github.io`.

## Публикация на GitHub Pages

*Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main`, папка `/ (root)`* → Save. Через минуту сайт будет по адресу `https://bektayevbaur.github.io/CR-CRM/`.

> GitHub Pages для **приватного** репозитория доступен только на платном тарифе GitHub. Варианты: сделать репозиторий публичным (секретов в коде нет — доступ к данным закрывают правила Firestore), либо разместить сайт на Firebase Hosting / Netlify / Cloudflare Pages.

## Лимиты бесплатного тарифа

Firestore Spark: 1 ГБ данных (≈ 4–6 тыс. фото), 50 000 чтений и 20 000 записей в сутки. Для одной сети точек этого хватает с запасом; при росте можно перейти на Blaze (оплата по факту) и перенести фото в Cloud Storage.
